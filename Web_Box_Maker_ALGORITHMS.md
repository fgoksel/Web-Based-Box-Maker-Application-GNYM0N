# Web-Based Box Maker — Algorithm Explanations

This document explains the core algorithms implemented in the project.

## 1) Geometry Generation (`GeometryEngine`)

### Internal dimensions
Given:
- External box size: `width (W)`, `depth (D)`, `height (H)`
- Material thicknesses:
  - frame thickness `tF`
  - base thickness `tB`

The engine computes:
- `iW = W - 2*tF`
- `iD = D - 2*tF`
- `iH = H - tB`

### Panel construction
The engine creates a list of `Panel` objects. Each panel includes:
- `panelWidth`, `panelHeight`, `thickness`
- `group`: `tray | lid | divider | inset`
- `outline`: initially a rectangle in 2D
- 3D placement: `position3D` + `rotation3D`

### 3D placement / grounding
For consistent visualization, the system uses a grounded coordinate system:
- External bottom plane is aligned to `y = 0`.
- The bottom panel is placed so it “sits” on the floor grid.

This alignment is critical for visual correctness when toggling lid/dividers.

### Optional components
The geometry generator optionally appends:
- Lid panels when `lid.enabled`
- Divider panels when `divider.enabled`
- Inset panels when `inset.enabled`

## 2) Finger Joints (`JointEngine`)

### Tab sizing (`computeTabSpec`)
The finger-joint logic selects:
- an odd tab count `count`
- a `tabWidth`
- a matching `gapWidth`

Constraints:
- tab width must be large enough for minimum strength: `minTabWidth = 1.5 * materialThickness`.
- tab count is reduced until the constraints are satisfied.

### Outline generation (`buildFingerJointOutline`)
The perimeter outline is generated by walking each edge and alternating between:
- tab segment points
- gap segment points

### Applying to panels (`applyJointToPanel`)
Depending on `joint.style`, the engine replaces:
- `panel.outline` with the new joint outline

This affects both:
- 3D extrusion shape
- SVG cut path shape

## 3) Panel Packing (`BinPacker`)

### Rectangle placement
The packing algorithm treats each panel as an axis-aligned rectangle with optional 90° rotation.

It maintains a list of `freeRects` (maximal empty rectangles).

For each panel, it finds the “best” free rect by a score:
- large waste area is penalized
- it also slightly biases toward stability (short-side preference).

### Splitting strategy
When placing a panel into a free rect, the free rect is split using a guillotine split:
- either split along width first or height first

### Overlap prevention
By only placing inside free rects and splitting free rects afterward,
the algorithm prevents overlap in sheet layout space.

### Overflow detection
If no free rect can fit a panel, the panel is marked `overflow: true`
and is skipped in SVG output.

### Grouped by thickness mode
When enabled, panels are grouped by `panel.thickness`.
Each group is packed independently into its own `SheetLayout` section.

## 4) SVG Generation (`SvgEngine`)

### Outline → SVG path
Each placed panel outline (possibly rotated in 2D) is converted to an SVG `<path d="...">`.

### Redundant point removal
Collinear points are removed with `removeCollinear(...)`
to reduce path complexity and output size.

### Path consolidation
Paths are consolidated by color group:
- multiple paths may be combined into fewer `<path>` elements.

### Export modes
- `generateSVG(layout, params)` outputs the normal single-layout SVG.
- `generateGroupedSVG(groupedLayouts, params)` stacks multiple layout sections
  in one SVG document for thickness-group mode.

## 5) Project JSON (`ProjectIO`)
The app exports/imports:
- `BoxParams`
- `SheetConfig`

Import validates the root structure and basic presence of `params`.
